# Portas do conector para o HT-9 de leitura: `mcpStatusOf` e `cliIsolation` (Tally, 05/11)

O que o host (`ConnectorPorts`, `connector-grants-host.ts`) pede ao runner. Funções estáveis, **síncronas** (o gate decide em microssegundos) e **sem modelo**. Prova: `persona-runners/tests/connector-ports.spec.ts` (14) e, na CLI real, `scripts/connector-ports-check.ts` (só contagens).

## `mcpStatusOf(cli)`: o pré-voo, com a anotação de cada ferramenta
```ts
import { mcpStatusOf, refreshMcpStatus } from '@deepseek-ai/dsh-persona-runners'

await refreshMcpStatus('claude')   // async, ZERO modelo, ~5 s: initialize + mcp_status. Retorna quantos servidores achou, ou -1 se a CLI não respondeu. Nunca lança.
mcpStatusOf('claude')              // SÍNCRONA: a última leitura, ou undefined se nunca houve refresh (aí o gate falha fechado: tudo vira send)
```
- **Quando chamar `refreshMcpStatus`:** quando a CLI é detectada no boot, quando a versão muda e quando a pessoa conecta/desconecta um conector. Uma leitura velha é segura: uma ferramenta nova ainda não provada é `send`; uma que deixou de ser só-leitura é pega pelo NOME (vale o mais estrito entre a anotação e o nome).
- **O que devolve** (formato enxuto, é exatamente o que o `annotationTable` lê): `[{ name, scope?, status?, tools: [{ name, annotations?: { readOnly?: true, destructive?: true } }] }]`. Só `true` exato vira anotação. **Não** guarda URL, instruções, esquemas, descrições nem conta.
- **Uso no host:** `annotations: tool => annotationTable(mcpStatusOf(cli) ?? [])(tool)` (o Anvil já faz). Há também `defaultMcpStatusCache.ageMs(cli)` para mostrar "verificado há N min".
- Medido na CLI real (2.1.318, a conta do Miguel, 05/11): 5,2 s para 21 servidores (8 conectados), 412 ferramentas, 228 provadas somente-leitura, 117 destrutivas. Zero chamada de modelo.

## `cliIsolation(cli, env?)` e `cliIsolationProven(cli, { version, env? })`: o nível de isolamento
| função | diz | usa-se para |
|---|---|---|
| `cliIsolation(cli, env?)` | o que o PLANO está configurado para fazer numa chamada COM ferramentas: `full`/`partial`/`none` | a tela e o contrato de concessão (ISO-2); é pura e já existia |
| `cliIsolationProven(cli, { version, env? })` | o que o produto ENTREGA agora: o plano, **mas só se a versão instalada da CLI foi PROVADA** (o isolamento só se aplica a uma versão provada; antes disso, e para uma CLI sem sonda, a chamada roda nativa) | o `loadedAlways` do cartão ("o conector fica sempre carregado"): dizer `full` de um lançamento que roda nativo seria afirmar um isolamento que não existe |
- Regras do `Proven`: plano que não muda o lançamento (Codex `partial`, Cursor `none`) mantém o nível; Claude em `needed` com veredito `ok` na versão = `full`; **sem a versão, sem veredito, `failed`, versão nova ou modo `native`/`answer-only` (chamada com ferramenta roda nativa) = `none`**; OpenCode, que o plano diz `full`, é `none` até ter sonda. Nunca passa do que o `cliIsolation` diz (testado).
- **Síncrona e sem sonda:** lê só o arquivo do gate (o veredito que a prova em segundo plano gravou). A versão vem do `probe` do host (`ConnectionView.version`). Hoje, com o padrão `answer-only`, uma tarefa COM conector roda nativa: `cliIsolation('claude')` e `Proven` dizem `none` e o cartão avisa que o conector fica sempre carregado; em `needed` provado, `full`.
- Medido na CLI real: plano `full`, provado `full` (2.1.318, `needed`), sem a versão `none`.

## `availableConnectorsOf(cli)`: os conectores conectados da conta (a mesma sessão)
```ts
import { availableConnectorsOf, defaultMcpStatusCache } from '@deepseek-ai/dsh-persona-runners'
availableConnectorsOf('claude')            // [{ name, url }] — SÍNCRONA, da última refreshMcpStatus; undefined se nunca houve refresh
defaultMcpStatusCache.accountsOf('claude') // o mesmo
```
- Sai do **mesmo** `refreshMcpStatus` (uma sessão de controle só, ~5 s): só `scope === 'claudeai'` + `status === 'connected'` + URL, uma por URL, com o `name` como a CLI dá ("claude.ai Gmail"; quem exibe tira o prefixo).
- **A URL é dado pessoal:** vive só nesta lista, em memória; **nunca** está em `mcpStatusOf`/`of()`, nunca é logada nem gravada em disco por este módulo (testado). É o id com que o host concede (ISO-5).
- Uma refresh seguinte substitui a lista (um conector que desconectou sai); uma refresh que falha (-1) mantém a anterior.
- A ponte do host fica: `availableConnectors ← availableConnectorsOf`, `connectorDefinitionOf ← 'account' se a URL está na lista`, `mcpStatusOf ← mcpStatusOf`, `cliIsolation ← cliIsolationProven`.

## O que NÃO está aqui
`connectorDefinitionOf` (a ponte decide: `account` se a URL está em `availableConnectorsOf`, `local`/`remote`/`missing` pelas outras fontes) e `connectorCostOf` (o pré-voo de custo por conector, `IsolationRuntime.connectorCostOf`, ~5 s, com o veredito guardado por versão) ficam com a ponte do host.

## D-096 (Atlas, 05/11): `needed` por padrão para as Tarefas, com dois fallbacks para o nativo — o sinal tipado do runner (combinado com o Anvil 04:48)
**O que muda.** `DEFAULT_CLI_ENV_MODE` passa de `answer-only` para `needed` (uma constante, um teste): toda chamada carrega só o que precisa e uma Tarefa recebe só os conectores que foram CONCEDIDOS (o piso de `needed` medido: 31.414 tokens/requisição contra 308.902 do nativo). `answer-only` e `native` seguem como chave (`PERSONA_CLI_ENV`).
**Fallback 1 (já existia, segue valendo).** A versão da CLI não foi PROVADA para `needed` (ou a prova falhou) → a chamada roda `native` com o motivo de sempre em `envModeReason` (`unverified`, `failed-version`, `parity-*`).
**Fallback 2 (NOVO): o conector CONCEDIDO não foi alcançado.** Decidido **antes do primeiro token**, dentro do `resolveRunner`, pelo pré-voo de conector (pedidos de controle, zero modelo; o mesmo de ISO-5). **NÃO há reexecução:** a Tarefa que rodaria em `needed` roda UMA vez, já nativa. A decisão é por chamada (por Tarefa): o runner de fallback **não entra no pool** e nada fica pegajoso — a próxima Tarefa reavalia (um veredito "não usável" da CLI é reprovado depois de 5 min).
- **Sinal (aditivo, no `usage()` onde já estão `envMode`/`envModeRequested`/`envModeReason`/`connectorsLoaded`/`connectorsDropped`):** `connectorsUnreached?: readonly { ordinal: number; reason: ConnectorUnreachedReason }[]` e `connectorsFallback?: 'native-once' | 'floor'`. `ConnectorUnreachedReason` = `'needs-auth' | 'no-login' | 'failed' | 'absent' | 'many' | 'timeout'`. Só aparece quando ao menos um conector concedido não chegou. **Códigos apenas:** nenhum URL nem nome sai do runner.
- **`ordinal`** = posição na lista `accountConnectors` que o host passou ao `resolveRunner`, **deduplicada por primeira ocorrência, na ordem recebida** (o host usa a lista de `forRunner` ordenada por `cli,id` e mapeia o ordinal de volta ao seu conector; Anvil 04:48).
- **`native-once`** (`absent`, `many`, `failed`, `timeout`): ESTA chamada roda nativa — `envMode: native`, `envModeRequested: needed`, `envModeReason: connector-unreached`. O nativo carrega TODOS os conectores da conta, então pode achar pelo nome o que a lista permitida por URL não achou. `connectorsLoaded`/`connectorsDropped` ficam fora (as contas do launch isolado não dizem nada verdadeiro sobre um nativo).
- **`floor`** (só `needs-auth` / `no-login`): o nativo TAMBÉM não alcança um conector que pede nova autenticação da pessoa, e custaria ~309 mil tokens por requisição à toa. A chamada segue em `needed` no piso, com os conectores que chegaram (`connectorsDropped` como hoje), `envMode: needed`; o host diz "reconecte {conector}" no detalhe da Tarefa. Decisão de detalhe do Tally, aceita pelo Anvil. Mistura (um `needs-auth` e um `absent`) → `native-once`.
- **Quem nunca cai em nativo por isto:** chamada SEM ferramentas (`permissionMode: deny`: conversa, triagem, 1ª entrega — nunca pede conector); CLI que não é Claude; e o caso em que o PRÓPRIO fallback 1 já fez a chamada nativa (a CLI carrega tudo; não há "não alcançou" a dizer).
**SEGURANÇA (a razão de existir do mandato).** No `native-once` a CLI carrega todos os conectores da conta. O que mantém a Tarefa dentro do que a pessoa concedeu é o **mandato do gate** (`PermissionGate.arm({ allowedServers })`, por turno, sem herdar; ver a seção anterior): o host **mantém o `arm` em toda Tarefa com conector, inclusive no `native-once`** (Anvil: sim). O runner não muda o gate; o teste GUARDA prova que o hook do gate segue no ÚNICO `--settings` da chamada nativa e que nenhuma ferramenta entra em regra de permissão.
**Do usage ao livro (Anvil 05:13).** `MeasuredUsage` (a entrada do `UsageMeterSink.record`) ganha, aditivos: `envModeReason?: string`, `connectorsUnreached?: readonly ConnectorUnreached[]` e `connectorsFallback?: ConnectorFallback`; o `withUsageMeter` os copia do `usage()` do runner SÓ quando existem (nunca inventa). O `usageStoreSink` (a porta do `persona-usage`) NÃO os repassa: o store de uso não tem coluna para eles; quem os grava é o sink do próprio host no `turn_ledger` (`env_mode_reason`). Testes: `usage-env-mode.spec` (+2).
**Host (Anvil).** Ledger + motivo no detalhe da Tarefa a partir de `envMode*` + `connectorsUnreached` + `connectorsFallback` (coluna `env_mode_reason` na migração do host, numeração combinada com o Bolt). Teste do host: Tarefa com conector inalcançável ⇒ UMA corrida nativa, motivo no livro e no detalhe, a próxima Tarefa reavalia (ele importa `unreachedWorld()` do spec do runner).
**Código.** `src/oar/connector-reach.ts` (política pura: `connectorFallback`, `unreachedReasonOf`, `NATIVE_CAN_REACH`), `IsolationRuntime.connectorsReach` (a mesma prova com o PORQUÊ; `connectorsReady` intacto), `resolve-runner.ts` (decide antes do 1º token, força nativo, não entra no pool), `env-mode.ts` (o usage diz), `contract.ts` (os tipos), `isolation.ts` (o padrão). **Testes GUARDA** (`tests/connector-unreached.spec.ts`, 19): o padrão é `needed`; a política pura; a prova com o porquê (absent/many/failed/timeout/no-login, versão desconhecida); alcançável = sem sinal; failed/absent/many/timeout ⇒ nativo UMA vez com o usage completo; needs-auth ⇒ piso; ordinal na lista deduplicada; nenhum URL no usage; fallback não entra no pool e a próxima chamada reavalia; chamada sem ferramentas nunca cai; fallback 1 (versão não provada) intacto; mandato do gate preservado.
**Limites conhecidos.** (1) Só o que o pré-voo enxerga: um conector que cai NO MEIO do turno é outro sinal (não está no D-096). (2) O pré-voo reflete a sessão isolada com a lista por URL; o nativo pode ainda não achar (o modelo diz que a ferramenta não existe): o custo do nativo uma vez é o preço aceito pelo Atlas. (3) As guardas do Probe (`persona-e2e/src/team-round-guard.ts` mata turno `native` e exige as provas de `answer-only` E `needed`; `team-round-tree-gate.ts` trata `answer-only` como o padrão) precisam aceitar, depois da virada, `native` COM `envModeReason: connector-unreached` e o padrão `needed` (o prewarm passa a provar só o modo em vigor).
