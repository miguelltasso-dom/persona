# @deepseek-ai/dsh-persona-engine

Native port of the MIT `dsh-superagent-prototype` engine (`src/core`, commit 8c32a9d; see `NOTICE`): synchronous commands, one transaction per command, effects after commit. Defines the repository ports; `persona-store` implements them.

Part of the Persona product group (`packages/persona/*`). See `persona-spec/PLAN.md` and `persona-spec/DECISIONS.md` (D-002, D-026).

When the host's connection cache is ready and has no usable engine, it calls `receive(trigger, { deferRouting: true })` before `engineUnavailable(trigger.id, reason)`. Intake stores the message and its queue position without subscription fan-out, wake, or executor effects. `no_engine_ready` carries only `triggerId`, `streamId`, and a typed connection reason; its deduplication marker persists in `TriggerDisposition.engineWait`. Ordinary intake remains immediate when there is no retained predecessor; new messages behind retained ones also wait, preserving per-stream arrival order.

The host owns replay when its cache becomes ready: iterate `pendingEngineTriggers()`, call `engineReady(id)`, and resume host routing only for the returned triggers, without receiving them again. Release applies subscription fan-out once; retries and out-of-order releases do nothing. `dismissEngineTrigger(id)` permanently suppresses a retained message. After `ENGINE_TRIGGER_CONFIRM_AFTER_MS` (24 hours), automatic release emits `engine_confirmation_required` once and retains the stream head. Only an explicit person confirmation permits `engineReady(id, { confirmed: true })`. These optional disposition fields extend Persona's existing JSON records; no Session format or SQLite schema version changes.

`measureFirstDeliveryAcceptance()` checks the scripted intake and assignment path. It does not prove real CLI execution. `verifyFirstDeliveryRun(evidence)` checks observations from a single app acceptance run: exactly one measured execution linked to its ticket and preferred connected CLI, no coordination/inject turn, delivery on #geral, a completed board card, one ready milestone, and elapsed time below the supplied limit. `FIRST_DELIVERY_MAX_PAID_TURNS` is 1 even if `maxCalls` retains a larger shared safety ceiling. Supply all calls from that run so coordination and retries cannot disappear from the count. The verifier starts no models and returns ordered failure ids plus measured token totals; missing or estimated usage fails real-execution verification. Clean-home setup, UI observations, runner timeout, and disposal remain the app harness's responsibility.

`firstDeliveryTask()` returns an answer-only assignment with `permissionMode: 'deny'`. The complete authorized company brief is inline; only the title is clipped. The assignment requires a textual summary and a proposed next task, without file access, commands, network requests, tool reports, recruitment, or execution of the proposed work. `firstDeliveryAsk()` carries that same assignment. The host must deliver the complete assignment rather than the clipped ticket title and preserve the deny permission.

For onboarding, the host binds trusted `PreRouteInput.firstDelivery: {executorId,title}` after authorizing the actor. The `first_delivery` rule assigns that roster member without an assessor/model call; user text alone cannot enable it. Budget, silence and task ACL still apply. The host consumes `personaId`, skips the coordination driver's start/delivery for this task, and sends `firstDeliveryExecutionPrompt({personaContext,task})` once to the worker. Persona context is in that logged execution input, with no separate prompt injection turn. The normal Ticket, Assignment, reporting, delivery and milestone lifecycle remains in place.

`createReviewDelivery(options)` detects an existing `.git` directory or worktree file in the selected folder or its ancestors without launching Git. Existing repositories keep `GitReviewDelivery`; ordinary folders use `HistoryReviewDelivery`, with metadata under `<personaHome>/history/<projectId>` and independent drafts under the supplied `worktreesRoot`. Construction, an empty summary, and an empty sweep create nothing; hosts call `prepare` only for tasks needing files. User folders receive no `.git`. Private snapshots use `hash-object --no-filters` and isolated indexes, preserving exact binary and document bytes without hooks or attributes. Office/Windows temporary files and nested `.git` metadata are excluded.

The host supplies the executable selected from PATH or bundled Git. Missing Git rejects with `HistoryReviewError.code = git_unavailable` and safe recovery guidance. `maxCopyBytes` defaults to 256 MiB of logical file sizes; `gitTimeoutMs` defaults to 30 seconds. `HistoryFileOps.copyFile` supports platform hydration and independent copies; writable hardlinks must not connect a draft to the user's file. Symlinks and unsafe project/ticket identifiers are rejected. Summary text is bounded and redacted; private draft records survive host restart, and `sweepOrphans` removes only recorded closed drafts.

Ordinary-folder applications return a `restorePointId`. `listRestorePoints()` lists safe point metadata and its available/undone/expired state; `undoApply(id)` restores exact pre-application bytes once for 30 days, blocking if affected files changed afterward. Git delivery retains its existing behavior and exposes no restoration capability. A process lock and shared queue serialize operations per private history. A private journal stages user bytes and review-record updates together; failures restore completed changes, and subsequent operations recover interrupted transactions before proceeding. An unknown later file version produces `recovery_required`, preserving the journal for explicit recovery.

Concurrent edits return `blocked` with `conflicts: [{path,user,persona}]`, where each side is a `{hash,mode}` version or null for deletion. After a person's choice, pass those exact versions back as `accept(ticket, mode, {conflicts:[{...conflict,choice}]})`; `choice` is `keep_mine`, `keep_persona`, or `keep_both`. Missing choices block every change, and stale choices reject with `conflicts_changed`. Keeping both preserves the user's filename and writes the persona's bytes under an unused ` (da persona)` suffix; deletion on one side retains the remaining version without inserting conflict markers. Undo after conflict resolution restores the state immediately before applying, including the person's concurrent edits. The host owns ACL, wire validation, and mapping typed failures into visible actionable reports; the client imports these response types with `import type` and owns persona names and localized labels.
