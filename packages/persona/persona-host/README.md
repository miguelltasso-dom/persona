The onboarding request starts its first delivery through Intake. When execution and the channel reply settle, the host persists `first_delivery`, completes the introductory task's review, and appends one milestone on `#geral`. `getFirstDelivery` returns the persisted status after reopening; `startFirstDelivery` also waits for completion and is idempotent. Runner failures produce `failed` without a success milestone. Each turn replaces the previous text and report; a failed worker report or an empty production reply cannot advance the task to review. Delivered model text has `source: runner` in the message feed. Channel errors carry `[[run-error:{code,provider,persona}]]` data for localized client presentation. Unload waits for pending work and runner disposal before closing SQLite.

The first execution receives the full inline assignment, including the company brief, after the connection probe finishes. Worker status keeps its diagnostic summary in `assignment.report.summary` and its human question in `ticket.attention.question`. The usage sink records provider, cache counters and task ID per call; coordination calls are triage and worker calls are execution. A measured sink suppresses the legacy usage fallback for that runner.

A rejected executor delivery blocks its running task and publishes a structured failure on the original stream. Measured usage committed before rejection remains in SQLite. Unknown exception text is not copied into the channel or diagnostic list; the host reports an actionable engine failure instead of leaving the task marked as running.

The opt-in host smoke is `scripts/first-delivery-real-cli.ts` (`PERSONA_REAL_E2E=1` or `PERSONA_REAL_CLI=1`). It counts unique `deliver` attempts, including injections, and refuses a fourth attempt across all resolved runners. Its JSON contains those attempts separately from diagnostic stages and measured ledger entries. `verifyFirstDeliveryRun` checks the measured execution, channel reply, completed board task, unique milestone and elapsed time; a blocked or unmeasured run fails acceptance. The counter preserves runner identity so text capture remains available.

Remote teams are opt-in through `connectRemoteTeam` / `acceptInvite`. The host replicates only selected channels, persists pending references and replay cursors, and imports messages without Intake or a new model turn. Revocation is durable and stops both sending and receiving; DMs never enter this queue. Invite secrets use `personaVault`, while SQLite stores routing and invite metadata. See `persona-spec/contracts/remote-team.md` for the Remote fields, local edge restriction, polling settings and two-profile proof. `issueInvite` returns a Promise and routes to the edge only for a connected project; callers must await it.

`getRemoteTeamAvailability` exposes the Cofre capability without secrets. Production Web hosts cannot connect or issue invites without Electron encryption: operations fail with the typed `vault-unavailable` Remote error before network access. Tests opt into `PERSONA_VAULT_TEST_CIPHER=1`; packaging must never enable it. Restored connections preserve their cursor and pause traffic when the Cofre is unavailable.

Engine readiness is available through `getEngineStatus` and `getOverview.engineStatus`. A definitively unavailable cached connection defers Intake routing and appends one `no_engine_ready` message immediately. The host checks connections while triggers remain deferred (`engineRetryPollMs`, default 15000 ms), then releases them once in stream order without a second receive. `retryEngine` forces a check; `dismissEngineTrigger` preserves the human message; `confirmEngineTrigger` requires its author or workspace owner to confirm work retained beyond 24 hours. See `persona-spec/contracts/engine-readiness.md`.

Context imports apply as one SQLite transaction. Reusing a proposal ID with identical content is idempotent; different content returns `conflict` and rolls back the batch. Paste previews identify the full body and type, so rules sharing a prefix remain separate records. Duplicate detection ignores the source footer and compares the normalized body within the same type.

Derived context omits citations with recognized credentials or labelled secret values before retaining them for prompts or Contexto usado. Body, document title and locator are checked independently with the core value detector; a restricted citation keeps its ID and mandatory flag with empty text. Unassigned password/token guidance remains available to the prompt. The source record remains unchanged in the Cofre.
