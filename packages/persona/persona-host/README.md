Public parameters must carry an explicit type (Typert gate).

Part of the Persona product group (`packages/persona/*`). See `persona-spec/PLAN.md` and `persona-spec/DECISIONS.md` (D-002, D-026).

The onboarding request starts its first delivery through Intake. When execution and the channel reply settle, the host persists `first_delivery`, completes the introductory task's review, and appends one milestone on `#geral`. `getFirstDelivery` returns the persisted status after reopening; `startFirstDelivery` also waits for completion and is idempotent. Runner failures produce `failed` without a success milestone. Each turn replaces the previous text and report; a failed worker report or an empty production reply cannot advance the task to review. Delivered model text has `source: runner` in the message feed. Channel errors carry `[[run-error:{code,provider,persona}]]` data for localized client presentation. Unload waits for pending work and runner disposal before closing SQLite.

The first execution receives the full inline assignment, including the company brief, after the connection probe finishes. Worker status keeps its diagnostic summary in `assignment.report.summary` and its human question in `ticket.attention.question`. The usage sink records provider, cache counters and task ID per call; coordination calls are triage and worker calls are execution. A measured sink suppresses the legacy usage fallback for that runner.

The opt-in host smoke is `scripts/first-delivery-real-cli.ts` (`PERSONA_REAL_E2E=1` or `PERSONA_REAL_CLI=1`). It counts unique `deliver` attempts, including injections, and refuses a fourth attempt across all resolved runners. Its JSON contains those attempts separately from diagnostic stages and measured ledger entries. `verifyFirstDeliveryRun` checks the measured execution, channel reply, completed board task, unique milestone and elapsed time; a blocked or unmeasured run fails acceptance. The counter preserves runner identity so text capture remains available.
